# 补偿重复的初值与短程数值诊断（2026-09-25）

本轮在训练定义修订 `d64bd84` 后，按授权探究两次补偿执行的差异。原论文的正负结果、模型、面板分数与 v11 数值锁保留；这里只增加事后执行定位证据。

## 直接结果

1. 原／重复九对 checkpoint 0 的全部171份 writer 参数／缓冲张量字节相同；optimizer、已存 Torch CPU/CUDA RNG、学习率、数据位置及完整目标顺序一致。历史没有保存 Python/NumPy 全局 RNG，不能声称全部进程状态均已审计。
2. 九对日志都从第3步出现总梯度范数差异。旧工程记录中不带C的三个条件也出现这一早期分叉；不能把它当作C独有故障。前两步日志标量相同不代表梯度张量相同。
3. 同一物理H100上的两次3步插桩重放，把首个已捕获差异缩小到第2步反传：输入投影与前两层卷积共6个梯度张量不同，最大相对L2约9.02e-8。已捕获前向张量、坐标和loss仍相同，参数更新后出现差异，下一步传播到loss。
4. 相同物理GPU上设置cuDNN deterministic=True后，两次重放的全部已捕获张量在第1–8步字节相同；第3步之后分别恢复各自checkpoint继续。benchmark和TF32在两条件中本来均关闭。两条件共22次更新，均正常完成。

## 论文处理

附录S.1及执行条件表不再写“未做初始张量审计”；增加明确标为post-hoc的短程定位及范围。没有改写补偿额外收益未在完整重训中重新确立的结论，也没有把短程确定性当作1536步效果重复。

[匿名诊断材料](../reproducibility/compensation_diagnosis/README.md)包含机器可读摘要、原始源码及独立哈希清单。它与生成分数表的v11锁分开；完整性校验只对历史评测资产计算哈希，没有读取面板分数或进行新评测。

## 解释及下一步

现有证据排除了保存初值不一致，并识别了一个可由cuDNN设置控制的早期数值分歧。它没有唯一确定历史首发kernel，也没有量化该分歧对最终额外收益差异的因果贡献。

后续若检验补偿收益的训练重复性，应保留旧执行，并在显式记录的数值设置下，用新增种子同期完整重训Native/Rotated×有/无C四臂；三种子为12组完整训练。该矩阵尚未启动，本轮仅完成历史审计与短程定位。先用现有Train/Dev确认新执行设置，不利用确认面板选择数值配置。

本轮沿用已通过的3项数值键测试，额外核对全部204个锁定输入、1830数值对象及生成表图未变。重新编译和S.1局部视觉检查通过，最终页数与匿名包仍留待收尾。
